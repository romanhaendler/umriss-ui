# How the table exports, what can be copied, and the snoozed alarm's words

Gathered on 2026-10-11 from the repository at 5d31cd85 for the grilling of the open points.

## 1. How the table exports today
Files: packages/table/src/export.ts (`csvOf`, `visibleColumns`), src/model/csv.ts (`asCsv`), src/unbound.tsx (`Export`, ~l.312-360), src/values.ts (`exportValue`), tests-unit/csv.test.ts, tests-unit/toolbar.test.tsx (l.257 "Export"), treeRows/serverMode tests. Examples: demo/examples/Export/01-download-a-file.tsx, 02-take-the-text.tsx.
- Rows: the FILTERED set across all pages (`projection().filtered`), in sort order. Not the page, not the selection (the selection is never read in export.ts). Tree: `projection().exported` = every row of the filtered tree in reading order, open or not, with a first column "Level" (`wording.levelColumn`, 1 for a root). Server mode: the page only (button reads `exportPageLabel` "Export page").
- Columns: visible only (hidden dropped), in shown order incl. pinned blocks (`visibleColumns`, shared with the screen "so they cannot drift"). Columns of kind "other" (no text form) are dropped unless they have their own `exportValue`. Header = `label ?? id`.
- Values: raw value, not the formatted text. `exportValue`: number stays number; Date becomes ISO string (`toISOString`); boolean becomes "ja"/"nein" (hard-coded, lower case, "data not label", NOT from wording); absent (null/undefined/NaN) becomes empty field; `exportValue` prop on a column maps an object value first. `format` is ignored. A `Computed` column goes through the same `e.read(row)` path (its computed value). No aggregate/footer values are written. No group rows or footer rows: `csvOf` writes data rows only (grep for group/footer/aggregate in export.ts: nothing).
- Writing (csv.ts): separator `;` (comma is the decimal separator, "German Excel expects exactly this"); CRLF; BOM U+FEFF prefixed ("without it German Excel opens UTF-8 as Latin-1"); quoting only if the field contains `"`, `;`, CR or LF, quotes doubled; numbers `String(n).replace(".", ",")`, no thousands grouping, "deliberately without Intl: meant to be read back exactly".
- German vs English wording: NO difference in the data. Decimal comma, `;`, ja/nein are fixed. Only the header labels (the column labels), the level column header, button label and default file name (`exportFileName`: en "table.csv", de "tabelle.csv") follow the wording. Spec umriss-table: "German is the only language shipped; the export follows German conventions" (.scratch/umriss-table/spec.md l.183). Dates are ISO in both.
- Hand-off: `Export` without `onExport` does `new Blob([text], {type:"text/csv;charset=utf-8"})`, `URL.createObjectURL`, a temporary `<a download=filename ?? wording.exportFileName>`.click(), revoke after 10 s (Safari). With `onExport(text)` it hands over the text and makes no file. Also `snapshot.asCsv()` / `t.asCsv()` returns the text.
- Recorded decisions: csv.ts header: "The function returns text and triggers no download. How the text reaches the user - file name, moment, whether a file is made of it at all - only the application knows." and "takes the *filtered* set, not the visible page... what the user writes out is what he filtered, no matter which page". unbound.tsx: "Export makes the file. The old rule - the library gives text, the application makes the file - remains as `t.asCsv()` and as `onExport`. But the part exists for exactly the case in which the application wants nothing further than a file". umriss-table spec story 20: "export contains the filtered set in the visible columns and order, with numbers as numbers, so that a spreadsheet receives data rather than formatted text"; l.136 "Sorting, search, export and footers operate on the value only"; l.138 absent = empty field; l.148 anything else "not exported". table-tree-rows spec l.270 and story 21 (level column "so the spreadsheet keeps the hierarchy"). table-server-mode issue 02: "the export writes the page, and its button reads 'Export page'".

## 2. What a caller can reach to copy rows
- `TableSelection<string>` (src/model/useTableSelection.ts): `selected: ReadonlySet`, `isSelected`, `toggle`, `toggleAll` (filtered set), `clear`, `allSelected`, `someSelected`, `count`. `useTableSelection(ids)` is the headless hook; pass to `useTable` as `selection` (types.ts l.615) or read `snapshot.selection` (l.719).
- `TableSnapshot<Z>` (types.ts l.663; `Table<Z>` extends it, `TableRef` = it minus setFilter/conditionOf): `rows`, `filtered`, `visible`, paging, `search`, `sort`, `hidden`, `order`, `pinned`, `widths`, `filter`, `selection`, `grouping`, `view`, `asCsv()`, `rowCount`, `server`.
- Selected rows as text today: no API. A caller can compute rows = `t.filtered.filter(r => t.selection.isSelected(rowKey(r)))` (they own `rowKey`) but gets no column-aware text: `asCsv()` ignores the selection, and visible-column list/`exportValue` are internal (`visibleColumns`, `csvOf` not exported from index.ts as far as the Export grep shows; `asCsv` model function is internal too). Selected text with the visible columns is not reachable without internals.
- Keyboard: no Ctrl/Cmd+C handler anywhere in src (ctrlKey/metaKey appear only in grid.tsx l.541-548 and parts.tsx l.1362 sort-additive click). Grid mode (grid.tsx onKeyDown on a cell): `if (event.altKey || event.metaKey) return;` then with ctrlKey only Home/End move; `if (event.ctrlKey) return;` -> so Ctrl+C / Cmd+C are left untouched and do the browser default (copies a text selection, nothing for an active cell). Space selects the row; Enter/F2 edit; printable keys start an edit.

## 3. ADR-0032 / comparison-roadmap
- ADR-0032 (docs/adr/0032-what-umriss-is-not.md l.45-52): "Cell range selection and undo. Both belong to a spreadsheet: a range is what one copies into Excel, and undo presumes the table owns the data... A clipboard for ranges goes with the ranges; copying rows stays among the "later" items of `.scratch/comparison-roadmap/spec.md`. *Instead:* undo in the application's state...; select rows, not ranges."
- comparison-roadmap/spec.md l.35-37 ("Later (can), not specified yet"): "Tree data (delivered...), clipboard, XLSX export, saved views, the schedule's utilisation view and print, Avatar, Timeline. Each waits for a caller who needs it." No further text on any of them there; "saved views" appears nowhere in ADR-0032.
- non-goals-and-honest-docs issue 01: "Clipboard is named only for ranges: comparison-roadmap keeps a row clipboard among its 'later' items, and table-grid-mode already points here."
- ADR-0034 l.70: "Range selection, a clipboard and undo stay out (ADR-0032): the grid walks cells, it does not select them." table-grid-mode spec l.48: same.
- XLSX: no ADR mentions it; research files (docs/research/...) mention competitors only.

## 4. Runtime dependencies
- @umriss-ui/table: no `dependencies`; `peerDependencies`: `@umriss-ui/core` workspace:^, react >=18, react-dom >=18. Only `exports`: "." (dist/table.js) and "./styles.css".
- Across the workspace: core, charts, table, schedule, calculation have no `dependencies` at all (peers only; schedule peers core+charts). Only private `@umriss-ui/demo` has dependencies (marked, sugar-high, typescript).
- German precedent: ADR-0019 (docs/adr/0019-two-wordings-ship-english-is-the-default.md): "German ships as GERMAN_WORDING behind the subpath export `@umriss-ui/core/wording/de`." Reason: "the subpath says without explanation that this is freight you take on purpose. An application that never imports it never pays for it". Core package.json exports: `"./wording/de": {"types":"./dist/de.d.ts","import":"./dist/wording/de.js"}` beside "." and "./styles.css". Completeness guaranteed by typing both `Wording`.

## 5. Snoozed alarm's words
- wording.ts l.450: `availabilitySnoozed: (until: string, by: string) => string;` (property with function type, not method syntax); l.453 `availabilitySnoozedShort: string;`. English l.869-870: ``(until, by) => `Snoozed until ${until} by ${by}` `` / "Snoozed". German de.ts l.298-299: ``(until, by) => `Zurückgestellt bis ${until} von ${by}` `` / "Zurückgestellt". Doc comment at wording.ts l.447-449.
- AlarmList.tsx: `availabilityWords` l.164-174 builds `{short, full}`: short = `availabilitySnoozedShort`, full = `availabilitySnoozed(end, snooze.by)` (end = time if same day as as-of, else dateTime). Used at l.430-438: if short === full a plain `<Badge>{short}</Badge>`; otherwise `<Tooltip content={full}>` around a Badge holding `<span aria-hidden>{short}</span>` (badge) plus `<VisuallyHidden>{full}</VisuallyHidden>` (screen reader). So badge = short, tooltip = full, SR = full.
- `Snooze` (alarmModel.ts l.117-124): `until`, `by`, `reason?` with comment "Why, when the application asked for one. The list does not show it."
- Lines to change for the list to show a reason: (a) wording.ts l.450 add optional param (e.g. `reason?: string`) and update doc l.447-449; (b) wording.ts l.869 English and de.ts l.298 German bodies to append the reason when present; (c) AlarmList.tsx l.173 pass `snooze.reason` as third argument; (d) alarmModel.ts l.122 comment "The list does not show it" becomes false; (e) badge (short) and SR/tooltip follow automatically via `full`; no change at l.430-438 needed unless the badge itself should show it. Any other doc of the prop (AlarmList docs, wording.ts register) and tests asserting the text would need review.
- Type compatibility: `Wording` is declared as `export interface Wording` (wording.ts l.27) with the entry as a function-typed property `(until: string, by: string) => string`. A caller's hand-written `wording` (provider prop is `Partial<Omit<Wording,"presets">>`, language/index.tsx l.35) with a 2-parameter function stays assignable to a type with a third optional parameter (fewer parameters are assignable; also true under strictFunctionTypes since it's a property, not a method). Not run through tsc here; this is from the declarations. A caller who CALLS the function is unaffected by an optional param. German `de.ts` and English default are contextually typed, so they compile either way.
