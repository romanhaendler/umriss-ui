# As-is: how umriss-ui documents props and types (audit, 2026-10-02)

Scope: the demo pages (site = `pnpm build:pages`, prerendered HTML = `packages/*/demo/.generated/pages.json`) and their agent twin (`llms-full.txt` / `packages/*/docs/llms-full.md`). Repo state: `main` @ `3b2fa14`, nothing tracked changed. Generated by running `pnpm --filter @umriss-ui/<pkg> props` for all five packages (writes only gitignored `demo/.generated/` + `docs/llms-full.md`).
Numbers come from `asis_props_types.scripts/analyze.mts` + `analyze2.mts` (next to this file; run from `packages/core` with `node --experimental-strip-types <script> <outdir>`).

## 1. The pipeline

| Step | File | What it does |
|---|---|---|
| Public set | `packages/<pkg>/demo/outline.ts` → `Page.types[]` | A type is "public" iff some page lists it in `types`. No second list. `Page.exports[]` = import line only, separate from `types`. |
| Gate entry | `packages/<pkg>/demo/props.ts` → `generateProps` + `generateLlms` | |
| Reader | `packages/demo/src/tooling/propsReader.ts` (`readProps`) | Hand-written against TS compiler API (no react-docgen). Reads **only the package's own `src/`**. |
| Gate | `packages/demo/src/tooling/props.ts` | `process.exit(1)` listing every prop with empty JSDoc. |
| Output | `demo/.generated/props.json` (gitignored) | `TypeEntry {name, parameter[], inherits?, omitted[], props[], alsoTakes?}` |
| Render (SPA) | `packages/demo/src/PropsTable.tsx` (via `Page.tsx`, `tooling/tables.ts`) | 4 cols Name/Type/Default/Description; `*` = required; `on…` props split to an "Events" sub-table only where `demo.eventsApart` (table, schedule). |
| Render (prerendered HTML + llms) | `packages/demo/src/tooling/llms.ts` `tableMarkdown()` | **Second renderer** of the same data (Markdown → HTML via `marked`). Writes "(required)" instead of `*`, no events split. |
| Appendix (agents only) | `llms.ts` `exportedDeclarations()` → "## The rest of the API" | `.d.ts`-emit of every `src/index.ts` export **not named in code anywhere on the pages**. Not on the human site. |

### Per prop extracted
| Field | Source | Notes |
|---|---|---|
| `name` | property signature | methods / index / call signatures are skipped by design (`membersOf`); none of the 134 current table types loses one (checked) |
| `type` | `node.getText()` — **raw source text**, whitespace-collapsed | no checker resolution, no alias expansion, no links |
| `optional` | `?` token | |
| `defaultValue` | **only** from the component's destructuring initialiser (`{ size = "md" }: XProps` or `forwardRef<_, XProps>`) | never from `@default`, never from prose; config-registration components (charts/schedule/calculation) therefore show almost none |
| `description` | `symbol.getDocumentationComment()` | **JSDoc tags are dropped** (`@deprecated`, `@param`, `@example`…) |
| `inheritedFrom` | parent type of this library, if exported | |
| table-level `inherits`/`omitted` | `extends XHTMLAttributes<…>` / `Omit` → one sentence "Also takes every attribute of `<button>` – without …" | |
| `alsoTakes` | intersection part that has its own table → "Also every prop of `ColumnBase` and `ValuePaths`." | plain `<code>`, no anchor link |
| `parameter[]` | type parameter **names only** | constraints/defaults dropped |

### Type rendering (answer to "how")
- Raw TS text as written: `ButtonSize`, `Accessor<T>`, `EditFor<W, Z>`, `"nice" | "data" | "visible" | readonly [number, number]`.
- Named aliases are **never expanded** – contradicts the reader's own header comment (`propsReader.ts` l.27: *"`"primary" | "secondary" | "ghost" | "danger"` is what the reader needs"*): the source says `variant?: ButtonVariant`, so the table says `ButtonVariant`.
- **No links** from a type cell to anything (`<code className="apiType">{prop.type}</code>`, `PropsTable.tsx` l.93). 33 props reference a type that *does* have a table somewhere (e.g. `RowFilter<Z, any>` in `TableOptions.rowFilters`) – still unlinked.
- Callbacks: signature shown verbatim (`(intent: Intent) => void`); payload types opaque in 19 of 97 callback props.
- Discriminated unions: merged into one table, differing shapes joined with `|` → artefacts like `never | FooterFor<W>` (see §5).
- Generics: kept generic (`T`), but constraints lost and helper-type parameters leak (`W` in `FieldColumn<Z, K>`).
- Description prose: renders `` `code` ``, `**bold**`, `[x](#/page)` (`Prose.tsx`). ADR/R-numbers are plain text, not links.

### The JSDoc gate – what it enforces
- **Only**: every prop in a listed type has a non-empty JSDoc body (`description !== ""`), unless inherited from another library type (then reported at the parent).
- Not enforced: description quality/length, default documented, value list documented, deprecation visible, every exported component/type has a table, every referenced named type has a definition.
- Companion guard `packages/demo/tests-unit/llmsGuard.test.ts`: every export appears in `llms-full` (true by construction via the appendix) and every export with a `<Name>Props` sibling is named by a page.
- Reader unit tests: `packages/demo/tests-unit/propsReader.test.ts` (fixtures; 16 cases).

### Where it runs
| Trigger | Runs gate? |
|---|---|
| `pnpm dev:<pkg>` (`predev`) | yes |
| `build:demo` (`prebuild:demo`) → `pnpm build:pages` → `.github/workflows/pages.yml` | yes |
| `pnpm typecheck` (`pretypecheck` in all 5 packages) → **CI** `.github/workflows/ci.yml` + `publish.yml` | **yes – CI fails on a missing JSDoc** |
| `prepack` (npm publish) | yes (also writes `docs/llms-full.md`) |
| `pnpm test:unit` | reader + llms guard tests |

Key mechanism: `llms.ts` puts an export into "The rest of the API" **only if no page names it in code**. Naming a type in a type cell (`ButtonSize`) or a function in an example therefore *removes* it from the only place its declaration would be printed. Verified: `ButtonSize`, `Accessor`, `TableRef`, `Present`, `Wording`, `ChartsWording`, `Intent`, `applyIntent`, `useTree`, `useToast`, `controlLimits`, `Formats` → 0 entries in any `llms-full.md` appendix. Appendix sizes: core 54, charts 68, table 39, schedule 8, calculation 0.

Unnamed-on-site (agent-appendix-only) examples – core: `TreeOptions`, `TreeSnapshot`, `UmrissConfig`, `LanguageProviderProps`, `GlyphProps`, `useVirtual`, `useLanguage`, `useUmriss`, `DEFAULT_WORDING`, `mergeLanguage`; charts: `SeriesConfig`, `AxisConfig`, `TooltipConfig`, `TooltipPoint`, `LegendConfig`, `ParetoOptions/Result/Item`, `ControlLimits`, `ruleRun/ruleTrend/…`, `toWorkingTime`, `DEFAULT_CHARTS_WORDING`; table: `ColumnPreset`, `CellEditorProps`, `AggregateFunction`, `SortDirection`, `AlarmRow`, `AlarmColumn`, `LifecycleState`, `PRIORITIES`, `ALARM_COLUMNS`; schedule: `MoveIntent`-siblings `LaneIntent`, `StretchIntent`, `LeadInIntent`, `LeadOutIntent`, `PlaceIntent`, `ResolvedAppearance`.

## 5. Poor type rendering – quoted from generated output

(From `table/demo/.generated/pages.json` / `props.json`.)

1. **Discriminated-union artefacts + leaked type param + lost deprecation** – `/column/`, `FieldColumn<Z, K>`:
   ```
   <td><code>footer</code></td><td><code>never | FooterFor&lt;W&gt;</code></td><td>—</td>
   <td>The old name of <code>aggregate</code> – not together with it.</td>
   <td><code>aggregate</code></td><td><code>never</code></td><td>—</td>
   <td>Not together with <code>footer</code>, its old name.</td>
   ```
   `aggregate` (the *current* prop) is typed `never`; its real type `AggregateFor<W, Z>` vanished; `footer`'s `@deprecated` is gone. Source `packages/table/src/types.ts` l.64-79.
2. **Free type parameter `W`** in a table whose header is `FieldColumn<Z, K>`:
   `edit : EditFor<W, Z>` · `editOptions : readonly Present<W>[]` · `validate : (value: W | null, row: Z) => string | null | undefined` · `footer : never | FooterFor<W>` (inherited from `EditOptions`, which has no table; "From `EditOptions`." in the cell). Also `TableSnapshot<Z>.conditionOf : <B>(filter: RowFilter<Z, B>) => B | null`.
3. **Constraint dropped**: header `FieldColumn<Z, K>` for `FieldColumn<Z, K extends Field<Z>>`; `RadioGroupProps<T>` / `RadioOption<T>` for `T extends string`.
4. **Alias instead of values**: `/button/` → `size | ButtonSize | — | "sm for … md otherwise. Default: the size of a ControlSizeProvider …"` (ButtonSize → ControlSize → `"sm" | "md"`, two hops, neither shown). Same for `TextProps.tracking : TextTracking` (not even exported).
5. **Core callback type hidden**: `/line/` → `accessor (required) | Accessor<T> | — | Y value; null/undefined/NaN/±Infinity means a gap (R-2.5).` – the `(d, index) =>` shape is not discoverable; 18 props across 7 series tables share it.
6. **Unimportable types**: `/search/` → `of | TableRef | — | The table, when the part does not stand inside it…`; `size : ToolbarSize` (not exported); `ValuePaths.groupValue : (value: Present<W>) => string | number | boolean | Date | Absent` (`Present`, `Absent` not exported).
7. **Type-expression noise**: `LanguageOptions.wording : Partial<Omit<Wording, "presets">> & { presets?: Partial<Wording["presets"]> }` – and `Wording` itself (288 keys) is shown nowhere.
8. **Default only in prose, column empty**: `TableOptions.pageSize | number | — | Default 10.`; `ChartProps.height | number | — | …300 without a value…`; `SliderProps.min/max/step = "Default: 0/100/1"`; `ScheduleProps.zoomLimits | ZoomLimits | — | Default: one hour to 28 days.`
9. **Internal references**: `UmrissProviderProps.language : LanguageOptions` – "Formats and wording, entry by entry. See `lib/language`." (a source path); charts' `(R-2.4)`, `(R-4.12)`, `(R-5.1)`, `(R-7.6)`.
