# @umriss-ui/schedule API

Generated by the props step (`pnpm --filter @umriss-ui/schedule props`); do not edit. First sentences only; the full text is `docs/llms-full.md`.

## Hooks

- useSchedule — Declares a schedule: hands back `Schedule` and the parts declared inside it - `Lane`, `LaneGroup`, `Subtasks`, `Dependencies`, `BlockedTimes`, `Milestones` -, its `view` and the setters `setView`, `setDomain`, `toggleGroup`, `foldAll` and `unfoldAll`, and `positionAt`, `clientPointOf` and `visibleDomain`.

## Functions

- applyIntent — The subtask as the intent asks for it.
- arrival — When a dependency has to have arrived at its subtask, by its anchor.
- departure — When a dependency leaves its subtask, by its anchor.
- findings — Every finding at once.
- inBlockedTime — Every subtask that covers blocked time on its lane, lead-in and lead-out included - once per blocked interval it covers, in the order of the subtasks.
- occupied — The interval a subtask occupies on its lane: lead-in and lead-out included.
- overlaps — Every pair of subtasks that cover each other on a lane.
- resolveAppearance — Settles a subtask's appearances into what is drawn.
- ripple — The moves that push every successor whose dependency no longer fits after `intent` - transitively, in the order they were first pushed.
- shiftTask — The moves that carry a whole task in time - every subtask of it by the same amount, so that its lengths and the distances between its stops stay as they were.
- snapTime — `time` onto the nearest line of the raster in local time - a step alone starts at local midnight.
- subtaskFromPlace — The subtask a place intent asks for, under an id the caller chooses.
- violatedDependencies — Every dependency whose successor is to be reached before the predecessor's departure plus the dependency's lag.

## Options and returns

### useSchedule

#### options (ScheduleOptions)

- initialView?: ScheduleView — The view to start from, read once when the hook first runs; a different value on a later render is ignored, as React ignores a changed `defaultValue`.
- onViewChange?: (view: ScheduleView) => void — Every change the planner makes, once, always the whole view - the one to keep, or to hand another schedule's `setView`.

#### returns (ScheduleParts)

- Schedule: (props: ScheduleProps) => ReactNode — The schedule.
- Lane: typeof Lane
- LaneGroup: typeof LaneGroup
- Subtasks: typeof Subtasks
- Dependencies: typeof Dependencies
- BlockedTimes: typeof BlockedTimes
- Milestones: typeof Milestones
- view: ScheduleView — How the planner is looking at the plan: the span and the folded groups.
- setView: (view: ScheduleView) => void — Goes to a whole view; what it leaves out is shown whole again.
- setDomain: (span: readonly [number, number] | null) => void — Puts a span of two wall-clock instants in view; `null` shows the subtasks' extent.
- toggleGroup: (id: string) => void — Folds or unfolds one **Lane group**.
- positionAt: (clientX: number, clientY: number) => { time: number; lane: string | null } | n… — The time and the lane at a client point, or null outside the plot - and null while no schedule is mounted.
- clientPointOf: (time: number, lane?: string) => { x: number; y: number } | null — The client point of a time - on the middle of a lane where one is named - or null while the schedule is not on screen.
- visibleDomain: () => readonly [number, number] — The visible span, as two wall-clock instants.
- foldAll: () => void — Folds every group.
- unfoldAll: () => void — Unfolds every group.
