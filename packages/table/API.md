# @umriss-ui/table API

Generated by the props step (`pnpm --filter @umriss-ui/table props`); do not edit. First sentences only; the full text is `docs/llms-full.md`.

## Components

- ColumnGroup — Puts a second head row over the `Column`s it wraps: one cell, spanning the group's visible columns.
- ColumnMenu — Show and hide columns and arrange them.
- Export — Writes the filtered set in the visible columns and their order – with the values, not with their presentation.
- Pagination — The pagination bar.
- Search — The table's search field: one text over every column that searches, in the table toolbar.
- Toolbar — The table toolbar: on the left whatever one puts into it, and the conditions of the column filters; on the right the ratio of the filtered set to all rows and "reset" as long as something restricts, and the count of the selection with the bulk actions.

## Hooks

- useTable — A table over your rows: the hook holds its state - sort, filters, search, grouping, page, selection, column widths -, and the parts it returns are typed at your row, so that a field name in `Column` is checked by the compiler.
- useTableSelection — A small headless helper for row selection: it holds the selection as a set and supplies the states for "select all" (including indeterminate).

## Functions

- column — A column preset that fits every table whose rows carry its field: create it once, outside the component, and spread it into a `Column`.
- columnFilter — A filter for columns with values of type `W` and conditions of type `B`.
- rowFilter — A filter over the rows of type `Z` with conditions of type `B`.
- tableModel — The table's pipeline as a pure function - filter, sort, page over rows and model columns.

## Constants

- csv — The CSV: the language's conventions; a column of days as the zone's day, other points in time as ISO text.

## Options and returns

### useTable

#### options (TableOptions)

- rowKey: (row: Z) => string — A stable key per row – the basis of selection and expansion.
- pageSize?: number — How many rows a page holds in flow, or with `maxHeight`, and the start value in a frame of definite height before it is measured: there a page holds the whole lines the frame leaves between the head and the pager. (default: 10)
- defaultSort?: SortLevel | readonly SortLevel[] | null — The application's sort; it is the default that `view` leaves out. (default: null)
- defaultGrouping?: GroupingId<Z> | readonly GroupingId<Z>[] — The application's grouping: a column or group key, or up to three, the outermost first. (default: ungrouped, until the user groups)
- preFilter?: (row: Z) => boolean — Which rows the table has at all – by permission, by tenant, by anything the user is not meant to undo.
- rowFilters?: readonly RowFilter<Z, any>[] — The row filters the table has: conditions the application defines over the whole row and sets with `t.setFilter(filter, condition)` from a control of its own.
- initialView?: TableView — The view to start from, read once when the hook first runs; a different value on a later render is ignored, as React ignores a changed `defaultValue`.
- onViewChange?: (view: TableView) => void — Every change the reader makes, once, always the whole view - the one to keep, or to hand another table's `setView`.
- virtual?: boolean | { overscan?: number } — Renders only what stands in the scroll area; paging is then off.
- selection?: TableSelection<string> — A selection from outside instead of its own – when the application holds it.
- onSelectionChange?: (keys: string[]) => void — Called with the selected keys after each change – the user's or the API's, its own selection or the one handed in – from an effect, never at mount.
