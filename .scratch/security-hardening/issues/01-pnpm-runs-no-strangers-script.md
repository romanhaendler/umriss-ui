# 01 - pnpm runs no stranger's script and takes no day-old version

Status: ready-for-agent
Type: task
Size: S

Blocked by: None (can start immediately)

## What to build

`pnpm install` runs the lifecycle scripts only of packages the workspace names,
and refuses versions published less than three days ago. The workspace moves to
the current pnpm major (at least 10.16); `packageManager` names it with its hash
and CI keeps reading it from there.

## Acceptance criteria

- [ ] `packageManager` names pnpm ≥ 10.16 with its hash; the lockfile is regenerated by that version.
- [ ] No dependency's resolved version changes in the lockfile diff beyond what the new major's format requires.
- [ ] The workspace settings set `minimumReleaseAge` to 4320 minutes.
- [ ] `onlyBuiltDependencies` lists exactly the packages whose install scripts the build and the tests need (found with `pnpm ignored-builds` after a clean install); an empty list if none are needed. Each entry's reason is the commit message's.
- [ ] After a clean install (`node_modules` removed), `pnpm check` passes and `pnpm test:visual:quick <package>` passes for every package.
- [ ] CONTRIBUTING.md (or wherever the required pnpm version is stated) names the new version.
