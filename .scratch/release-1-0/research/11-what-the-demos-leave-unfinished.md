# What the demos leave unfinished

Ticket: `issues/11-what-the-demos-leave-unfinished.md`. Read only: nothing was built, installed, run or changed.

## Method and a gap in the inputs

- `packages/<pkg>/demo/.generated/props.json` and `.generated/twins/` do not exist in this worktree for any of the
  seven packages. The ticket's mechanical count therefore could not read "Shown in" from `props.json`. Instead the
  count below matches each prop listed under `## Props` in `packages/<pkg>/API.md` (checked in, generated by
  `pnpm --filter @umriss-ui/<pkg> props`) against the `examples/` and `examples.ts` sources of the package's demo.
  A prop counts as shown when it appears as `name=` or `name:` in that source. This is a proxy: a prop written as
  a playground `controls` string (the `demo/configurators/*.tsx` files) is not seen, and a JSX child (`children`) is
  not seen either, so the counts are a ceiling of unshown props for the examples.
- `packages/schedule/API.md` has no `## Props` section, so schedule's props cannot be counted from it. Its examples
  exist (26 folders) but its props are unmeasured.
- The package-level checked-in file `packages/<pkg>/demo/unshown.json` already lists props the demo knows are not
  shown, each with a reason. It is the demo's own admission list and is counted separately below.

## Findings

1. **Core: 42 props show in no example, most only as playground controls.** `clearable` is on eight components
   (`Input`, `Select`, `Combobox`, `MultiSelect`, `ColorPicker`, `DatePicker`, `DateRangePicker`, `DateTimePicker`,
   `DateTimeRangePicker`, `TreeSearch`); it is listed in `demo/configurators/*.tsx` `controls` arrays
   (e.g. `DatePicker.tsx:11`, `Combobox.tsx:18`), not in an example. Other examples-less props include
   `Popover.focusRef`, `Popover.insideRefs`, `Popover.restoreFocus`, `Popover.hideOnScroll`, `Popover.closeOnTabOut`,
   `Popover.onBlur`, `Textarea.autoGrow`, `Textarea.showCount`, `Textarea.resize`, `Input.numeric`, `Link.external`,
   `Meter.showLabel`, `ProgressBar.showLabel`, `Badge.pill`, `Card.collapsible`, `Card.defaultCollapsed`,
   `DateTimePicker.withSeconds`, `TimeInput.withSeconds`. Several of these are the props a 1.0 reader looks for first
   (`Card.collapsible`, `Link.external`).

2. **Table: no example sets a list filter through `initialView` (ticket claim verified).** `filter="list"` appears in
   `Filter/01-list-filter.tsx:26-27` and `Column/06` and `Column/07`, always as a column prop. The `initialView` uses
   are `Filter/08` (`rowFilter` `overdue`), `Filter/10-text-filter.tsx:25` (text `startsWith`/`endsWith`),
   `Toolbar-controls/03` (`conditions: { heavy: 20 }`, a range), `Grouping/09` (`folded`), `View/01` and `View/02`.
   None is a list condition. Table's one unshown prop is `Search.grow` (`unshown.json` lists `Search` only for
   `className`, `onValueChange`).

3. **No example filters a boolean column (ticket claim verified).** Boolean fields appear in examples as `overdue`
   (`Row-appearance/02-styling-rows.tsx:10`), `pages` (`Column/03-defaults.tsx:10`), `failed`
   (`Filter/08-a-question-over-several-fields.tsx:163`, filtered only through a custom `rowFilter`), `signed`
   (`Export/02`, `Export/05`) and `approved` (`Edits/08`). No column with a boolean value carries `filter=`. Per
   `packages/table/src/types.ts:81-86`, `FilterFor` accepts `"list"` for any displayable value, so a boolean column is
   typed as filterable but no example shows it.

4. **Thin or uneven coverage at 1.0.** `dashboard` has one example folder (`Dashboard`) and `alarms` has four
   (`AlarmBanner`, `AlarmList`, `PriorityMark`, `Trips-and-floods`), against 26 for `schedule` and about 90 for core.
   `schedule/demo/examples/findings` is the one lower-case folder name in schedule's examples, where its siblings are
   Capitalised or hyphenated (not checked across the other packages). `calculation` has 11 example folders. These are candidates; whether they are
   unfinished depends on the product scope the maintainer sets.

5. **The package's own unshown list is the admission list, and it is long for core and charts.** `unshown.json` holds
   17 core entries (for example `SplitButtonProps.menuLabel`, `RadioGroupProps.name`, `SegmentedControlProps.name`,
   `AlertProps.dismissLabel`), 19 charts entries (`ChartProps.ref`, `ChartProps.className`, `ChartProps.style`,
   `AreaProps.color`), 8 table entries (mostly `className` pass-throughs and `VerdictBase.*` twins), and 1 each for
   schedule and calculation, 2 for dashboard, 0 for alarms. Some carry the reason "not shown yet", e.g.
   `SearchProps.onValueChange` in `packages/table/demo/unshown.json`: "the examples move to the field contract's names
   with the callers' migration". That is a migration deferred to after the demos, and it touches a prop name that 1.0
   would freeze.

## Not found

- No placeholder or leftover text (`TODO`, `FIXME`, `TBD`, `lorem`, `xxx`, `placeholder text`, `coming soon`) in any of
  the seven demos' `.ts`/`.tsx` sources.
- No example with an empty `lead`: every `lead = ""` search returned zero.
- The page structure and the look were not judged (out of scope per the ticket).
